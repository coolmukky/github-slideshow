Proctor Evaluation Cheat Sheet

Quick at-the-table scoring aid — grade each team fast against these anchors. Full reference answers are in the ZTA Proctor Guide. Do not show participants.

How to score. Each use case = 100 pts: Mapping 40, Products 30, Diagram & solution 30. Tick what a team hits, award partial credit where intent matches, then total. 1–3 required, 4–5 bonus.

Use Case 1 — Managed Environment — Segmentation

Required 100 pts
① Pain-point → product mapping · 40 pts
  • VLAN/subnet segmentation too complex → propose SGTs (TrustSec) instead of VLAN/IP.
  • Profiling can’t keep up → Cisco ISE (cloud AI) profiling.
  • Failing PCI → SGT segmentation + insert FW (FTD) where L7 is required.
  • PCs behind on AV / OS → ISE Posture + remediation before full access.
  • No budget for firewalls → SGT / SGACL on existing switches (no new FW).
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: ISE · ISE-SGT · ISE SGACL policy · ISE pxGrid · Catalyst SD-WAN · FMC / SCC / FTD · Cisco Secure Workload

③ Diagram & overall solution · 30 pts
  • Labels all four groups: Employees, IOT, deskagents, Guest.
  • Marks the enforcement point(s) — SGACL on switches/routers; FW (FTD) where L7.
  • Honors access rules: IoT → DC + Internet only; Guest → Internet only; deskagents → on-prem DC only.
  • Reuses the existing network — no wave of new firewalls.
Common gaps / red flags — dock marks
  • Relies on VLANs / IP ACLs for segmentation.
  • Buys new firewalls just to segment (ignores budget pain).
  • No posture story for the AV / OS pain.
  • Guest not restricted to Internet-only, or IoT not restricted from other groups.

Use Case 2 — Remote Workers — Zero Trust Access

Required 100 pts
① Pain-point → product mapping · 40 pts
  • Over-permissive VPN → Secure Access ZTNA (per-app least privilege).
  • Manual daily VPN → Secure Client always-on / seamless ZTNA.
  • Too many sign-ons → Duo SSO.
  • Passwords / stolen creds → Duo passwordless (FIDO2/passkeys).
  • Okta too costly → Duo as SSO/IdP.
  • Block gambling/gaming → Secure Access SWG + DNS security.
  • Contractors, unmanaged → clientless ZTNA (RDP/VDI). Branch cost → SD-WAN + Secure Access = SASE.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Cisco Secure Access (SSE) · Cisco Duo · Cisco Secure Client · Catalyst SD-WAN · Umbrella / DNS security

③ Diagram & overall solution · 30 pts
  • Shows ZTNA (client + clientless) path to private apps, replacing broad VPN.
  • Marks the SSE point of enforcement for internet control (SWG/DNS) and per-app policy.
  • Contractors reach apps via clientless ZTNA only; corporate via least-privilege ZTNA.
  • SASE branch: SD-WAN + Secure Access; identity via Duo (passwordless / SSO).
Common gaps / red flags — dock marks
  • Keeps broad client VPN as the primary access (not Zero Trust).
  • No passwordless / phishing-resistant MFA story.
  • Contractors given client VPN instead of clientless ZTNA.
  • No SWG/DNS control for gambling/gaming.

Use Case 3 — AI Access and Agent Controls

Required 100 pts
① Pain-point → product mapping · 40 pts
  • Shadow AI → Secure Access CASB / discovery (report usage).
  • Fine-grained per-user control → identity policy (Duo/ISE) + ZTNA.
  • Only corporate ChatGPT tenant → SWG tenant restrictions; block personal login.
  • No sensitive data to GenAI → AI Defense + DLP.
  • Claude Desktop / MCP agents → AI Defense guardrails + egress control.
  • Unknown MCP servers in DCs → Secure Workload / Hypershield discover + allow-list.
  • Risky model downloads → SWG file inspection + AI Defense model validation.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Cisco AI Defense · Cisco Secure Access (CASB / SWG / DLP) · Cisco Duo · Secure Workload / Hypershield

③ Diagram & overall solution · 30 pts
  • Shows AI egress (managed devices + Claude Desktop agents) routed through Secure Access with AI Defense inspection.
  • Enforces corporate-tenant-only ChatGPT and blocks personal credentials.
  • DLP on prompts/uploads to prevent sensitive-data exposure.
  • MCP-server flows in private/public DCs discovered and allow-listed (Secure Workload / Hypershield).
Common gaps / red flags — dock marks
  • Only blocks AI outright (no fine-grained, identity-based control).
  • No DLP for data shared with GenAI.
  • Ignores local agents (Claude Desktop) and MCP-server flows.
  • No discovery/reporting of shadow AI.

Use Case 4 — Merger & Acquisition — Extend Segmentation

Bonus 100 pts
① Pain-point → product mapping · 40 pts
  • Extend segmentation → TrustSec SGT propagation (SXP / inline) via SD-WAN, policy from ISE.
  • Selected users → Site 9951 resource → SGT-based SGACL enforced at FTD/switch.
  • Not ready to onboard 100 staff → federate acquired Okta to ISE/Duo (SAML).
  • Minimize disruptive auth → SSO / identity federation (Duo).
  • Breached, still passwords → Duo MFA + passwordless for acquired users.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Cisco ISE · Cisco TrustSec (SGT) · Secure Firewall (FTD) · Cisco Duo · Catalyst SD-WAN

③ Diagram & overall solution · 30 pts
  • Shows SGTs extended from HQ to the acquired site over SD-WAN, enforced at the on-site FTD.
  • Only the selected group reaches the Site 9951 restricted resource (SGACL).
  • Acquired Okta federated to ISE/Duo — no bulk directory re-provisioning.
  • Acquired users get MFA / passwordless immediately.
Common gaps / red flags — dock marks
  • Re-subnets or rebuilds VLANs to extend segmentation instead of SGT.
  • Bulk-imports 100 users into the corporate directory (ignores the quick-federation ask).
  • Leaves acquired users on passwords (no MFA/passwordless).
  • Opens the Site 9951 resource to all branch users.

Use Case 5 — Zero Trust across Multicloud Data Center

Bonus 100 pts
① Pain-point → product mapping · 40 pts
  • No app visibility → Secure Workload App Dependency Mapping (on-prem + AWS + Azure + K8s).
  • No segmentation plan → Secure Workload auto-policy + validation.
  • K8s latency/visibility → Hypershield (eBPF).
  • Runtime protection / blast radius → Hypershield autonomous segmentation.
  • Can’t patch IoT → Hypershield virtual patching.
  • Disparate mgmt interfaces → Security Cloud Control (unified).
  • Budget / native → Multicloud Defense + virtual appliances.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Cisco Secure Workload · Cisco Hypershield · Cisco Multicloud Defense · Security Cloud Control · Secure Firewall (FTDv)

③ Diagram & overall solution · 30 pts
  • Shows app discovery + microsegmentation spanning on-prem, AWS, Azure and Kubernetes.
  • Runtime protection / autonomous segmentation to minimize blast radius (Hypershield).
  • Virtual patching for unpatched IoT.
  • Single management plane (SCC); native enforcement + virtual appliances to fit budget.
Common gaps / red flags — dock marks
  • Buys hardware firewalls everywhere (ignores budget / native-first).
  • No app-discovery / dependency mapping before segmenting.
  • Ignores Kubernetes runtime and IoT patching.
  • Leaves multiple disparate management consoles.
