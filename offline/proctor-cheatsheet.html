Proctor Evaluation Cheat Sheet

Quick at-the-table scoring aid, aligned to the official Solution Guide. Full reference answers are in the ZTA Proctor Guide. Do not show participants.

How to score. Each use case = 100 pts: Mapping 40, Products 30, Diagram & solution 30. Tick what a team hits, award partial credit where intent matches, then total. 1–3 required, 4–5 bonus.

Use Case 1 — Managed Environment — Segmentation

Required 100 pts
① Pain-point → product mapping · 40 pts
  • VLAN/subnet complexity → Implement SGTs instead of VLAN/IP subnets.
  • Profiling can’t keep up → ISE cloud AI profiling.
  • Failing PCI → SGT segmentation + FW services where L7 is required.
  • PCs behind on AV/OS → ISE Posture + remediation.
  • No budget for firewalls → SGTs enforce segmentation in the existing wired/wireless network.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: ISE · ISE-SGT · ISE SGACL · ISE pxGrid · Catalyst SD-WAN · FMC/SCC/FTD · Cisco Secure Workload

③ Diagram & overall solution · 30 pts
  • An SGT per group and correct SGT-Matrix rules: IOT → DC + Internet only; Guest → Internet only; Mac-mini → on-prem DC only.
  • Enforcement on the existing switches (no new firewalls); FW services inserted only where L7 (PCI) is needed.
  • Employees profiled via 802.1X/WebAuth; IOT and Mac-minis via MAB/profiling.
Common gaps / red flags — dock marks
  • Relies on VLANs / IP ACLs instead of SGTs.
  • Buys new firewalls just to segment.
  • No ISE Posture story for the AV/OS pain.
  • SGT Matrix leaves Guest or IOT over-permitted.

Use Case 2 — Remote Workers — Zero Trust Access

Required 100 pts
① Pain-point → product mapping · 40 pts
  • Over-permissive VPN → Zero Trust Access (Secure Client → Secure Access).
  • Manual daily VPN → ZTA module auto per-app tunnels.
  • Too many sign-ons → Duo Passport SSO.
  • Passwords / stolen creds → Duo advanced passwordless.
  • Okta too costly → Duo Directory.
  • SASE branches → SD-WAN into Secure Access with Direct Internet Access.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Secure Access · Secure Client (ZTA + VPN Full Tunnel) · Secure Access Private Resources proxy · Duo (Passport/Directory/Passwordless) · Secure Access VPNaaS · Secure Access Unified Policy · SD-WAN (SASE) · SWG

③ Diagram & overall solution · 30 pts
  • ZTA per-app for modern apps; full VPN kept only for selected legacy apps.
  • SWG blocks gambling/gaming categories; contractors reach apps via browser-only (clientless RDP).
  • Duo Passport SSO + advanced passwordless; Duo Directory replaces Okta.
  • SASE = Secure Access + Catalyst SD-WAN (IPsec / Direct Internet Access).
Common gaps / red flags — dock marks
  • Keeps broad client VPN as the primary access (not Zero Trust).
  • No passwordless / Duo Passport story.
  • Gives contractors client VPN instead of browser-only clientless access.
  • No SWG category control for gambling/gaming.

Use Case 3 — AI Access and Agent Controls

Required 100 pts
① Pain-point → product mapping · 40 pts
  • Shadow AI → Secure Access AI Access (discover & control AI usage).
  • Unknown/over-privileged MCP servers → Secure Access AI Gateway (register & manage MCP servers).
  • Personal ChatGPT credentials → Secure Access tenant controls.
  • Risky model downloads → Secure Access semantic inspection.
  • Fine-grained control + Claude Desktop agents → Duo IdP agent registration (DCR) / fine-grained authorization.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: AI Access within Secure Access · AI Gateway within Secure Access · Secure Access tenant control · Secure Access semantic inspection · Duo IdP (DCR) · (Cisco AI Defense DLP)

③ Diagram & overall solution · 30 pts
  • AI egress (managed devices + Claude Desktop agents) routed through Secure Access AI Access with guardrails/DLP.
  • AI Gateway registers and allow-lists MCP servers; local agents (Claude Code) governed via Duo authorization.
  • Tenant control enforces the corporate ChatGPT tenant and blocks personal logins.
  • Semantic inspection blocks risky AI models.
Common gaps / red flags — dock marks
  • Only blocks AI outright (no fine-grained, identity-based control).
  • No MCP-server registration/governance (AI Gateway).
  • Ignores local desktop agents / Duo agent registration.
  • No tenant control or model inspection.

Use Case 4 — Merger & Acquisition — Extend Segmentation

Bonus 100 pts
① Pain-point → product mapping · 40 pts
  • Extend segmentation → SGT capability in remote FTD; inline tagging HQ→remote.
  • Not ready to onboard 100 staff → Duo Directory + SCIM import from Okta.
  • Minimize disruptive auth → Duo SSO routing rules (Okta coexists).
  • Breached / passwords → Duo Passwordless.
  • Selected users → Site 9951 → source & dest SGTs in remote FTD policy; SCC pushes SGT policy into SD-WAN.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: FMC/FTD (S2S VPN + inline SGT) · Duo Directory (SCIM) · Duo SSO routing · Duo Passwordless · SCC

③ Diagram & overall solution · 30 pts
  • Site-to-site VPN from the acquired-site FTD to HQ FTD; SGTs extended via inline tagging.
  • Only the selected group reaches the Site 9951 restricted resource (source/dest SGT in FTD).
  • Duo Directory hosts the 100 staff via SCIM from Okta — no bulk corporate-directory onboarding.
  • Duo SSO routing keeps Okta working during transition; acquired users get passwordless.
Common gaps / red flags — dock marks
  • Re-subnets / rebuilds VLANs instead of extending SGTs.
  • Bulk-imports 100 users into the corporate directory (ignores the quick Duo-Directory/SCIM ask).
  • Leaves acquired users on passwords (no Duo passwordless).
  • Opens the Site 9951 resource to all branch users.

Use Case 5 — Zero Trust across Multicloud Data Center

Bonus 100 pts
① Pain-point → product mapping · 40 pts
  • No app visibility → Secure Workload App Dependency Mapping (on-prem + AWS + Azure).
  • No segmentation plan → Secure Workload auto-baseline policy (discover → validate → enforce).
  • Kubernetes latency/visibility → Isovalent (Cilium/eBPF) + Tetragon runtime.
  • Can’t patch IOT → segment + runtime protection as compensating control.
  • Disparate mgmt interfaces → Cisco Cloud Control (SCC) unifies UIs.
② Products — how & why / differentiators · 30 pts
  • Names a specific product with a correct one-line “how it works”.
  • Gives a genuine “why / differentiator”, not a generic benefit.

Expected set: Cisco Secure Workload (CSW) · NGFW/FTD · Isovalent (Cilium/eBPF/Tetragon) · ISE (pxGrid common policy) · Cisco Cloud Control (SCC)

③ Diagram & overall solution · 30 pts
  • CSW App Dependency Mapping discovers apps/flows across on-prem, AWS, Azure and Kubernetes.
  • Auto-baseline microsegmentation; ISE shares SGT/identity context via pxGrid to CSW and FTD.
  • Isovalent/Cilium/Tetragon for K8s runtime protection; virtual appliances (FTDv) to fit budget.
  • Single management plane via Cisco Cloud Control (SCC).
Common gaps / red flags — dock marks
  • Buys hardware firewalls everywhere (ignores budget / native-first).
  • No App Dependency Mapping / discovery before segmenting.
  • Ignores Kubernetes runtime (Isovalent/Cilium) and IoT compensating controls.
  • Leaves multiple disparate management consoles.
